## Agent Bridge connect timeout fix (chat chain)

The v0.7.17 rewrite of `AgentBridgeClient.connectSocket()` computed the connect
deadline as `min(Date.now() + connectRetryMs, request deadline)`. Callers that
passed `connectRetryMs: 0` (notably `ensureBridgeReadyForChatRun`, used before
every chat run) got `effectiveDeadline = Date.now()`, so the loop threw
"Agent bridge connect timed out" **before ever attempting a connection** — even
when the broker was reachable. Chat sessions failed with
"Agent Bridge is not reachable" immediately after login.

Fix: `connectRetryMs: 0` now means "no retries" rather than "give up before
trying". The retry window is only applied when `connectRetryMs > 0`; otherwise
the request-level deadline still bounds the connect phase, guaranteeing at
least one real connection attempt. A single failed attempt with
`connectRetryMs <= 0` fails fast without entering the retry loop.

## Meeting / group-chat panel display-name sync

Merging `org/meeting/v0.73` into main brings WeChat (Token Platform) device
login, super-admin binding, and profile display-name synchronization. Profile
display names (e.g. the bound WeChat nickname) are Web-UI metadata only
(`~/.hermes-web-ui/profile-metadata/`) and never touch the underlying Hermes
profile directory, so chat/group-chat surfaces can show a friendly name while
all requests keep using the system profile name.
