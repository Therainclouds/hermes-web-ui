# 统一灰盒检测附录

## 1. 使用说明

本附录配套 `graybox-testing-standard.md` 使用，提供以下落地内容：

- 检测清单
- 执行手册
- 记录模板
- 问题整改流程
- 版本报告模板

使用要求如下：

- 每次版本部署后先复制本附录模板，再开始实际填写
- 一个版本对应一套独立检测记录
- 检测记录必须保留原始证据链接、截图、日志或命令输出
- Blocked 项不得删除，必须保留原因和补测计划

## 2. 执行手册

### 2.1 检测准备

执行前按以下顺序确认：

| 序号 | 检查项 | 说明 | 结果 |
| --- | --- | --- | --- |
| 1 | 版本确认 | 明确项目名、版本号、构建时间、部署时间、部署人 | 待填写 |
| 2 | 环境确认 | 明确生产或等价预发布环境、设备信息、访问地址 | 待填写 |
| 3 | 依赖确认 | 数据库、systemd、NetworkManager、浏览器、外部接口等已就绪 | 待填写 |
| 4 | 工具确认 | Postman/Apifox、浏览器、日志工具、系统命令可用 | 待填写 |
| 5 | 账号确认 | 测试账号、设备账号、必要权限已准备 | 待填写 |
| 6 | 变更确认 | 已拿到本次版本核心变更清单 | 待填写 |

### 2.2 执行顺序

必须按以下顺序执行：

1. 后端接口灰盒检测
2. 前后端联调链路检测
3. 端到端业务流检测
4. 配置完整性与权限复核
5. 基础性能稳定性复核
6. 问题汇总、复测与结论输出

### 2.3 证据要求

每一类检测至少保留以下一种证据：

- 请求响应记录
- 浏览器抓包
- 页面截图或录屏
- 服务日志
- systemd 或系统命令输出

## 8. 问题整改与复测流程

整改流程固定如下：

1. 检测执行人登记问题并附证据
2. 开发负责人确认问题级别和根因
3. 发布负责人判断是否阻断放行
4. 开发修复后提交修复说明
5. 原检测人优先复测，必要时交叉复测
6. 复测通过后更新状态为已关闭
7. 未通过则重新打开问题并保留原记录

复测记录模板如下：


## 9. 工具配置建议

### 9.1 Postman 或 Apifox

- 为两个项目分别建立环境
- 使用变量保存主机地址、token、profile、设备 ID、版本号
- 每次导出或保存集合前清理敏感值
- 为核心接口建立正向、异常、回归三类用例分组

### 9.2 浏览器工具

- 开启 Network 保留日志
- 关键链路导出 HAR
- Console 报错必须截图并记录时间
- Application 面板需检查 token、localStorage、sessionStorage 的敏感项

### 9.3 系统与日志工具

- `systemctl status <service>`
- `journalctl -u <service> -n 200 --no-pager`
- `ss -lntp`
- `curl`
- 设备侧必要时补充 `top`、`free -m`

## 11. 最低执行要求

每次版本部署后，至少要保证以下动作被执行并留痕：

- 通用检测清单全部执行
- 对应项目专属清单全部执行
- 问题单全部登记
- 复测记录完整
- 输出版本灰盒检测报告
