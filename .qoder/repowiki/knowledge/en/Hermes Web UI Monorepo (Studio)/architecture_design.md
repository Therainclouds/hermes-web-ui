The repository is a TypeScript monorepo organized into distinct product boundaries: `packages/client` (Vue 3 + Vite frontend), `packages/server` (Koa BFF with routes/controllers/services/db/middleware), `packages/desktop` (Electron shell that boots the local server and manages updates), `bin` (CLI entrypoints for daemon lifecycle and the `hermes-studio-mcp` stdio server), `hermes_data` (Python pyudev-based USB device watcher), and `tests` (Vitest unit/integration plus Playwright E2E). The BFF server owns HTTP/WebSocket endpoints, authenticates requests, and orchestrates side effects through services that call the Hermes agent bridge, SQLite stores, file I/O, and subprocesses. The desktop package bundles the same server and serves it locally, while the CLI (`hermes-web-ui`) manages its own process lifecycle. Cross-cutting concerns — OpenAPI generation, device packaging, update manifests, and release workflows — are driven from top-level scripts under `scripts/`. Product boundaries are enforced by keeping Web UI logic separate from host bootstrap, Hermes Agent lifecycle, and device-runtime concerns, with update/distribution contracts centralized in `docs/update-distribution/`.
