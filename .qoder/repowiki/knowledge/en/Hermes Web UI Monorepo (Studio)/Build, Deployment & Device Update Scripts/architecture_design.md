The scripts directory is a flat collection of independent utility scripts organized by concern rather than sub-packages:
- Build & bundling: `build-server.mjs` (esbuild-based Node server bundle), `build-device-package.mjs` (tar.gz device image with allowlist/host-dependency manifest), `generate-openapi.mjs` (static AST scanning of Koa routes/controllers), `clean-dist.mjs`, `check-release-consistency.mjs`.
- Device packaging & deployment: `export-device-image.sh`, `verify-device-image.sh`, `deploy-source-armbian.sh`, `install-device-package.sh`, `update-source-deploy.sh`, `bootstrap-device-to-device-package.sh`, `bootstrap-device-from-v0.6.14-to-v0.6.15.sh`.
- Runtime update orchestration: `hermes-web-ui-update-runner.sh` reads a JSON request, validates an allowlisted env set, then dispatches to either `update-source-deploy.sh` or `install-device-package.sh`; `hermes-web-ui-update.service` / `hermes-web-ui.service` are systemd unit files consumed by the runner.
- Shared helpers: `update-task-state.py` (atomic JSON state file for long-running tasks), `verify-terminal-runtime.mjs` (post-build marker assertion), `guard-no-inline-data-urls.mjs` (CSP safety guard), `generate-server-cert.sh`.

Dependency direction is one-way: high-level orchestrators (`hermes-web-ui-update-runner.sh`) call lower-level installers/deployers; build scripts import only local helpers like `verify-terminal-runtime.mjs`. All scripts resolve their own `SCRIPT_DIR` and operate relative to the repo root or a configured `DEPLOY_DIR` (`/opt/hermes-web-ui`). There is no shared library — each script is self-contained and invoked directly from CI, systemd, or the running application.
